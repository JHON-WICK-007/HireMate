SESSION STATE — Font FOUT Fix (Navbar Pop on Hard Refresh)
Date: 2026-07-04
================================================================================

## Problem
On hard refresh (Ctrl+Shift+R) of the resume-builder page, the Navbar's left
links and profile name briefly shrink then return to normal size. This is a
FOUT (Flash of Unstable Text) caused by font re-downloading competing with
next/font/google preloading. Only happens on resume-builder, not other pages.

## Root Cause
preview.tsx injected <link> tags for Google Fonts into the component's DOM
subtree (inside a <div>, not <head>). On hard refresh:
1. next/font/google preloads Inter/Outfit from <head>
2. preview.tsx <link> tags trigger RE-DOWNLOAD of the same Inter font
3. The browser briefly re-evaluates font metrics → Navbar text shrinks
4. Once fonts settle, text returns to normal size

Additionally, @import url() inside CSS style strings caused redundant
double-loading of fonts.

## Investigation Findings
1. display: "block" would cause FOIT (invisible text up to 3s) — REJECTED
2. Template CSS variables (--font-display, --font-body, etc.) shadow global
   globals.css definitions with hardcoded font names
3. next/font/google generates @font-face with hashed names (e.g.,
   __Playfair_Display_abc123), so templates MUST use var(--font-*) references
4. Both <link> tags AND @import url() loaded same fonts — redundant
5. React places <link> tags in component's DOM subtree, not <head>
6. T1 <link> didn't include Inter, but @import did — asymmetry found
7. No other font-loading mechanisms exist (@font-face, font-display, etc.)
